# AIOS S3-compatible API

Embedded S3 front-end in `aiosd` (optional). Objects are files in a **POSIX volume** via `libaios_posix`, so the same paths are visible to FUSE (`aios-fuse`) and `aiosfs` when mounted on that volume.

## Enable

```yaml
http_listen: "0.0.0.0:7480"   # required (S3 mounts posix over loopback HTTP)
s3_listen: "0.0.0.0:7481"
s3_volume: s3                 # POSIX volume name
s3_access_key: aios           # global SigV4 access key id (root)
# global secret = cluster_key
```

CLI: `--s3-listen`, `--s3-volume`, `--s3-access-key`.

## Mapping

| S3 | POSIX (volume = `s3_volume`) |
|----|------------------------------|
| Bucket `photos` | Directory `/photos` |
| Key `2026/a.jpg` | File `/photos/2026/a.jpg` |
| `s3://photos/2026/a.jpg` | Same file via FUSE at `…/photos/2026/a.jpg` |

Multipart staging uses `/.s3multipart/` (hidden from `ListBuckets`).

## Auth

AWS Signature Version 4 (`AWS4-HMAC-SHA256`). Path-style only: `http://HOST:7481/bucket/key`. Region: any (commonly `us-east-1`); must match the Credential scope.

### Global root key

- Access key: `s3_access_key` (default `aios`)
- Secret: `cluster_key`
- Access: all buckets; creates keep default POSIX owner (`0:0` unless changed elsewhere)

### Per-bucket IAM keys

Opaque access key ids mapped to **uid/gid** and a **bucket allowlist**. Managed via admin API / CLI / web UI; stored as CAS JSON object **`s3iam/{s3_volume}`**.

| Field | Meaning |
|-------|---------|
| `access_key_id` | Opaque string (e.g. `photos-rw`) |
| `secret` | Random secret (shown once on create) |
| `uid` / `gid` | POSIX owner applied on creates under allowed buckets |
| `buckets` | Allowlist of bucket names |

IAM keys may only operate on allowlisted buckets (`ListBuckets` filtered; others → `AccessDenied`). New files/dirs created with that key get `setattr` uid/gid so FUSE/POSIX ownership matches.

```bash
aios --cluster-key "$KEY" --endpoint 127.0.0.1:7480 admin s3-cred create \
  --id photos-rw --uid 1001 --gid 100 --buckets photos
aios --cluster-key "$KEY" --endpoint 127.0.0.1:7480 admin s3-cred list
```

Admin HTTP: `GET|POST /admin/api/s3/credentials`, `DELETE /admin/api/s3/credentials/{id}` (cookie or HMAC). Web UI: **S3 credentials** tab.

## Supported ops (v1)

- CreateBucket / DeleteBucket / HeadBucket / ListBuckets
- PutObject / GetObject / HeadObject / DeleteObject (Range GET)
- CopyObject
- ListObjectsV2 (`prefix`, `delimiter`, `max-keys`)
- CreateMultipartUpload / UploadPart / CompleteMultipartUpload / AbortMultipartUpload

Metadata: `Content-Type` → xattr `user.aios.s3.content-type`; `x-amz-meta-*` → `user.aios.s3.meta.*`.

## awscli example

```bash
export AWS_ACCESS_KEY_ID=aios
export AWS_SECRET_ACCESS_KEY="$KEY"   # same as cluster_key
export AWS_DEFAULT_REGION=us-east-1

aws --endpoint-url http://127.0.0.1:7481 s3 mb s3://mybucket
aws --endpoint-url http://127.0.0.1:7481 s3 cp ./file s3://mybucket/path/file
aws --endpoint-url http://127.0.0.1:7481 s3 ls s3://mybucket/

# Same object via FUSE (volume=s3):
#   aios-fuse -o endpoint=127.0.0.1:7480,cluster_key=$KEY,volume=s3 /mnt/s3
#   cat /mnt/s3/mybucket/path/file
```

## Limits

- No virtual-host style, IAM policies beyond bucket allowlists, versioning, lifecycle, or Select
- Nested prefix ACLs inside a bucket are not modeled
- S3 requires `http_listen` so posix can reach the object API on loopback
- Large puts go through the posix striping path (same cost as FUSE writes)
